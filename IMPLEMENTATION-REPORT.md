# Реализация repo-evaluation-kit v1

Создан компактный комплект для исследования нескольких репозиториев относительно
новой цели: методика, шаблоны, инструкции трёх действий, переносимый skill,
локальная механика и проверки. Это первая проверенная на ограниченных сценариях
версия; универсальность для всех предметных областей не заявляется.

## Что реализовано

- [README.md](README.md) — использование из текущей папки, короткий запрос,
  продолжение, машинный вход, перенос и состав поставки.
- [Основной skill](.agents/skills/repo-evaluation/SKILL.md) — вход «цель + ссылки»,
  условия применения, компактный маршрут и поэтапное подключение ресурсов.
- [Методика](.agents/skills/repo-evaluation/references/methodology.md) — этапы А–Е,
  три независимых оценки, статусы доказательств/запусков, инвентаризация форков,
  сравнение архитектур, ревью, границы и критерии завершения.
- [Форматы](.agents/skills/repo-evaluation/references/formats.md) и
  [шаблоны](.agents/skills/repo-evaluation/assets/) — исходный запрос, критерии,
  реестр, доказательства, карточки, матрица, синтез, проверки и STATE.
- [Продолжение и смена цели](.agents/skills/repo-evaluation/references/continuation.md)
  — восстановление по файлам, сохранение старых решений, переиспользование фактов
  на том же commit и отдельное обоснование при изменении версии.
- [Промпты](prompts/) — START-AUDIT, CONTINUE-AUDIT, REASSESS-GOAL.
- [kit.py](.agents/skills/repo-evaluation/scripts/kit.py) — проверка входа,
  создание отдельного каталога, проверка структуры/ссылок и части противоречий.
  Python 3.10+, только стандартная библиотека, без сети и исполнения кандидатов.

Основные правила не дублируются в промптах, README и AGENTS. Все обязательные
ресурсы skill находятся внутри его каталога. Если Python недоступен, методика
и ручное создание файлов по шаблонам остаются применимыми.

## Происхождение и границы

[EXTRACTION-NOTES.md](EXTRACTION-NOTES.md) содержит фактический набор чтения,
универсальные принципы, предметные исключения и сознательные изменения.
Изучены верхние документы образца, структура INVENTORY, все templates/prompts,
три разных типа карточек и все пять запрошенных материалов OneBase.
Повторное исследование кодовых баз `_sources/` не проводилось.

Обобщены цель/критерии, инвентаризация, доказательства, карточки, общий корпус,
ревью, архитектурный синтез и продолжение. Специфические языки, платформы,
репозитории, приоритеты и исторические результаты не стали требованиями ядра.
Урок разных ролей сохранён: функция, подсистема и платформа могут дополнять
друг друга; архитектурная гипотеза не переписывает цель пользователя.

Исходные 49 файлов образца сверены по SHA-256 до и после работы: изменений
содержимого, удалений или новых файлов не обнаружено. Его программы не запускались.
Git-репозиторий не создавался; commits, push, PR, настройки, PATH и службы не менялись.
Глобальная установка skill не выполнялась.

## Проверка применимости

Выполнена [реальная демонстрация](examples/file-policy/2026-09-16-overview/REPORT.md)
первичного статического обзора двух публичных Python-библиотек для локального
отчёта о файловой политике: python-pathspec и editorconfig-core-py.
Зафиксированы два commit, 22 источника, 14 утверждений и две записи NOT_RUN.
Документы, манифесты и значимые участки кода прочитаны через GitHub connector;
кодовые базы не клонировались, зависимости не устанавливались, программы не запускались.

Результат не имитирует общий рейтинг: matcher и получение настроек имеют разные
роли, а проверка содержимого, диагностика и отчёт требуют собственной работы.
Готовность интеграции оставлена неизвестной; следующий эксперимент ограничен
одним маленьким деревом. Самопроверка всего обзора и отдельное независимое
контрчтение трёх участков явно разделены в протоколе.

Синтетические отрицательные случаи отделены от реальных проектов в
[fixture](tests/fixtures/reassessment.json). Их применение и восстановление
состояния описаны в [BEHAVIORAL-RESULTS.md](tests/BEHAVIORAL-RESULTS.md).
Автоматические проверки механики и их результаты —
[VALIDATION-RESULTS.md](tests/VALIDATION-RESULTS.md).
Все 25 тестов прошли. Отдельно проверена полная копия поставки без образца:
локальные ссылки, демонстрация и те же тесты работают. Пересмотр цели проверен
на сохранённой истории, затем отдельный агент восстановил результат с новым
контекстом только по файлам. Все пять обязательных отрицательных случаев учтены.
Проверка структуры не является доказательством достоверности аудита.

## Оформление skill

Перед созданием открыт актуальный официальный документ OpenAI:
[Build skills](https://learn.chatgpt.com/docs/build-skills), 16.09.2026
(переход с `developers.openai.com/codex/skills/`). Использованы обязательные
`name`/`description`, структура с внутренними references/assets/scripts и
загрузка подробностей по мере надобности. Путь локального skill соответствует
описанному `.agents/skills`. Автоматическое обнаружение в новой сессии приложения
и глобальная установка не проверялись; README предлагает явное чтение файла.

## Ограничения и следующий запуск

Проверены ограниченный обзор двух библиотек и искусственные случаи. Полный
глубокий аудит, фактическая интеграция внешних проектов, работа всех Git-хостингов,
обнаружение skill в других клиентах и исполнение на других ОС не подтверждены.
Удалённые URL и семантика Markdown-якорей не проверяются механическим валидатором;
подлинность commit, корректность диапазонов и смысл выводов проверяет исследователь.

Для нового исследования достаточно запроса:

> Прочитай .agents/skills/repo-evaluation/SKILL.md. Моя цель: …
> Репозитории: … Начни со статического обзора и сохрани отдельный запуск.

Для переноса копируется весь `.agents/skills/repo-evaluation/` в новый проект
или другой доступный каталог с явным указанием SKILL.md. Исходный пример не нужен.
Полная поставка описана в README; `.gitignore` исключает исторический образец,
новые результаты и локальные кодовые базы, не удаляя их.

Новые исследования и дальнейшее развитие после этой демонстрации не начаты.
