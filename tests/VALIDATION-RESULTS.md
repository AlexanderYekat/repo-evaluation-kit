# Проверки первой версии

Дата: 2026-09-16. Среда собственных проверок: Windows 11, Python 3.12.14,
стандартная библиотека. Исполнялись только механика комплекта и собственные
проверяющие сценарии; сторонние проекты и исходный образец не запускались.

## Автоматические проверки механики

**PASS — 25 тестов, без пропусков**, код завершения 0.
[Исходник тестов](test_kit.py), [вывод запуска](kit-tests.txt).
Воспроизведение из корня комплекта:

```sh
python -X utf8 -B -m unittest discover -s tests -v
```

Проверены минимальный вход, неверные типы/поля и дубли ключей JSON, учёт повторов
и недоступного кандидата, потерянные/подменённые входы, обязательные карточки,
сломанные/выходящие наружу ссылки, отдельные проекты и запуски, внешний каталог,
отказ от перезаписи, безопасные имена и защита образца на искусственном стенде.

Отдельные отрицательные контроли проверяют пустой PASS, skipped-only и mocks-only
интеграцию, недостающий протокол, приписанный результат NOT_RUN, неподходящее
доказательство утверждения, несовпадающий commit и противоречащие идентичности
дубликата. Реальный неуспех с assertions может подтвердить ограниченный вывод
об ошибке. Неизвестная версия/происхождение сохраняется с предупреждением,
а не заменяется вымышленными данными для прохождения проверки.

Тест переноса копирует один skill в отдельный временный каталог и выполняет
`check-kit`, `init`, `check-run` без исходного образца и абсолютных путей автора.
Шаблоны проверяются после создания настоящего каталога: их ссылки относятся
к будущему результату, а не соседним файлам assets.

**PASS — полная переносимая поставка.** По явному списку из README создана
временная копия всего комплекта без образца, `evaluations/` и `tests/.tmp/`.
В ней прошли `check-kit`, проверка демонстрации и все 25 тестов; образец не
появился и после исполнения. [Протокол](distribution-check.json).

## Применение и содержательная проверка

[Внешняя демонстрация](../examples/file-policy/2026-09-16-overview/REPORT.md)
использует реальные чтения двух публичных репозиториев на закреплённых commits.
`check-run examples/file-policy/2026-09-16-overview` — PASS, код 0,
две ожидаемые диагностические записи NOT_RUN. Лог —
[kit-check.txt](../examples/file-policy/2026-09-16-overview/sources/kit-check.txt).
Самопроверка и независимое контрчтение трёх участков описаны в её VALIDATION.

[Отрицательные случаи и смена цели](BEHAVIORAL-RESULTS.md) используют только
[явно синтетическую fixture](fixtures/reassessment.json). Выполнены 54 отдельных
автоматических проверки сохранённых артефактов, включая 22 неизменных SHA-256
исторических файлов, сохранение прежних фактов, две версии `check-run` и
отклонение искусственного пустого PASS. Это проверки артефактов, не 54 теста
реального продукта и не автоматическая оценка обоснованности рекомендации.
Дополнительный агент с новым контекстом восстановил v2, роли, ограничения и
следующий шаг только по сохранённым файлам; ответ вручную сверён с состоянием.

## Формат skill и границы валидации

Корректность frontmatter проверена чтением и `check-kit`; name/description и
схема размещения сверены с актуальной официальной документацией, ссылка в
[отчёте реализации](../IMPLEMENTATION-REPORT.md).

Дополнительный bundled `skill-creator/scripts/quick_validate.py` был вызван,
но завершился до проверки: `ModuleNotFoundError: No module named 'yaml'`.
Статус этого отдельного инструмента — **BLOCKED: отсутствует PyYAML**;
его результат не назван PASS. Зависимости не устанавливались. Сам комплект
PyYAML не использует, его собственные проверки выполнены.

Механика не проверяет истинность заявленного числа assertions, достоверность
источника, смысл рекомендации, Markdown-якоря и живые удалённые URL. Их проверяют
чтение и содержательное ревью. Обнаружение skill в другом приложении, работа
на других ОС и фактическая интеграция внешних проектов не проверялись.
