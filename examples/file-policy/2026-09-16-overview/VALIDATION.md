**OVERVIEW.** Сейчас выполнены чтение источников и самопроверка выводов. Все тесты, сборки, benchmark и интеграционные запуски исследуемых проектов — **NOT_RUN**. Технического сбоя окружения не установлено, поэтому они не помечены BLOCKED. Причина — явно ограниченное разрешение задачи.

## Выполненная самопроверка

Это **самопроверка автора демонстрации**, не независимый аудит.

1. Сверены идентичности обоих входов и получены commits из /commits/master. SHA fetch_file отдельно хранится только как file_blob_sha в квитанциях.
2. Сильное утверждение README о Git проверено против реально прочитанных участков. Вывод сужен до «реализация matcher найдена»; полная эквивалентность Git не заявлена.
3. Роль EditorConfig проверена по возвращаемому значению API: оно выдаёт свойства. Утверждение «готовый checker найден» отклонено; отсутствие checker во всём проекте не заявлено.
4. README и источник о чтении конфигурации сопоставлены: OSError подавляется. Это сохранено как основание для проверки диагностики, не объявлено доказанным эксплуатационным дефектом.
5. Метки лицензий API и pyproject сопоставлены с LICENSING/COPYING. Простые выводы «оба MIT» или «одна метка полностью описывает условия» отклонены.
6. Наличие r01 assertEqual отделено от прохождения теста. У r02 tests обнаружен как gitlink; assertions и результат внешнего корпуса не выдуманы.
7. Общая архитектура отмечена INFERENCE; реальная зависимость проектов друг от друга не утверждается.

Основания: c01-engine, c01-test, c01-license, c02-engine, c02-io, c02-test, c02-license в [EVIDENCE.json](EVIDENCE.json). Минимальные квитанции чтения — [sources/receipts.json](sources/receipts.json).

## Следующий эксперимент — план, не выполненные тесты

Цель: установить, можно ли через публичные API получить правильный отчёт на одном маленьком дереве без изменения его файлов.

Предусловия: отдельное разрешение выполнения стороннего кода и получения зависимостей; выбранная ОС и Python>=3.10; изолированное временное дерево; проверенные пакеты/исходники именно закреплённых commits; выбранный путь работы с лицензионными условиями. В текущей задаче эти действия не выполняются. Точная команда будет записана после создания проверяющего harness, сейчас команда не выдумывается.

Корпус должен проверять:

- F1: ordinary.txt проверяется, scratch.tmp исключается правилом *.tmp.
- F2: keep.tmp после отрицания !keep.tmp снова попадает в проверяемый набор; отдельно проверить исключённую директорию, не смешивая ожидания.
- F3: корневой .editorconfig задаёт LF и финальный перевод строки; вложенный меняет один параметр. Сравнить точные effective properties.
- F4: root=true прерывает поиск выше этой конфигурации; никакая политика за разрешённой границей не влияет на результат.
- F5: файл с ошибкой конца строки или завершающими пробелами даёт ожидаемую запись отчёта; корректный файл не даёт ложного нарушения.
- F6: ошибка доступа к конфигурации отличима от отсутствующего файла. Способ воспроизведения зависит от ОС; если не воспроизведён, отметить конкретную блокировку этого сценария.
- F7: hashes и список всех входных файлов до и после совпадают; отчёт создаётся вне входного дерева.
- F8: неверный относительный путь к r02 даёт ожидаемую ошибку, которая представлена пользователю, а не потеряна.

Ожидаемые результаты определить до исполнения, с assertions полного набора выбранных файлов, свойств, диагностик и hashes. Указать command, environment, commit, лог, число выполненных проверок/пропусков и фактический результат. Нулевая коллекция, одни skips или mocks не подтверждают интеграцию.

Граница: максимум 8 файлов и 8 перечисленных сценариев, один выбранный runtime, без benchmark, услуг сети и исправления файлов. Остановиться после одного полного прогона; при ошибке подготовки устранить только её и повторить затронутые проверки. При необходимости расширить набор кандидатов или изменить цель сохранить состояние и вернуться к постановке задачи.

Критерий решения: при совпадении всех ожидаемых результатов сохранить композицию; при несоответствии определить виновный контракт и проверить минимальную адаптацию либо замену конкретной подсистемы. Не расширять этот эксперимент в полный аудит автоматически.
