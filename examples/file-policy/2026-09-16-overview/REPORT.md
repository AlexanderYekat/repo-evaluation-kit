# DEMONSTRATION — общий вывод

Для локальной проверки файлов есть два подходящих кандидата на разные части задачи: **python-pathspec** может дать движок ignore-сопоставления, **editorconfig-core-py** — получение эффективных правил оформления. Это позволяет обоснованно рассмотреть отказ от написания обоих движков с нуля. Общий отчёт о нарушениях, контроль границ чтения и проверка неизменности файлов остаются собственным слоем. Следующий шаг — небольшой корпус с ожидаемыми результатами и проверка композиции на закреплённых версиях.

**Граница вывода: OVERVIEW, первичный статический обзор. Сторонний код не выполнялся, зависимости не устанавливались; все запуски NOT_RUN.** Решение условное. Лицензионные метки расходятся с более подробными документами; полного лицензионного, безопасностного и интеграционного аудита нет.

## Основание решения

В r01 найдены значимые участки компиляции patterns, вызова matcher и simple backend; в r02 — основной путь от get_properties к поиску, чтению и слиянию .editorconfig. Это SOURCE, а не RUN. Точные commits, пути и строки записаны в [EVIDENCE.json](EVIDENCE.json); разбор каждого кандидата — [r01](reports/r01.md), [r02](reports/r02.md).

Полезность высока в разных ролях, готовность продукта ещё не установлена, доказанность ограничена документацией и чтением кода. Нет оснований выбрать «победителя»: при заданной цели их сочетание является более содержательной гипотезой, чем соревнование по одному рейтингу (INFERENCE из c01-role/c02-role).

## Предлагаемая архитектура и её цена

Собственный слой выбирает разрешённую область дерева, загружает применимые ignore-правила и использует публичный API r01 для отбора. Для оставшихся путей он получает свойства через r02, сравнивает ограниченный набор свойств с содержимым и выдаёт отчёт. Предложенная передача данных между библиотеками **PROPOSED_INTEGRATION — ещё не проверенная интеграция**.

Такой вариант предполагает Python-окружение, поскольку таковы оба кандидата; по манифестам общая нижняя граница — Python 3.10 (c01-runtime/c02-runtime). Это только совместимое пересечение заявленных требований, не результат установки. Платформенную основу всей системы оба проекта по просмотренным материалам не предлагают; они заменяют две подсистемы.

Собственный слой нужен для границ дерева, правил обработки ошибок, чтения содержимого и отчёта. Начать можно с конечного перевода строки, завершающих пробелов и вида конца строки. Это предложение объёма первого эксперимента, не утверждение о полной поддержке всех свойств EditorConfig.

## Ревью

Выполнена самопроверка автором демонстрации: c01-engine/c01-test/c01-license, c02-engine/c02-io/c02-test/c02-license сопоставлены с точными участками прочитанных источников. Полная Git-эквивалентность, готовый checker, прохождение тестов и единая лицензия отклонены как чрезмерные выводы. Отдельный агент review_demo независимо перепроверил только s01-check/s01-backend внутри c01-engine и s02-io для c02-io; существенных замечаний в этом объёме нет. Это не независимый аудит всей демонстрации. Возражения ниже сохраняют решение условным. Протокол — [VALIDATION.md](VALIDATION.md).

## Что может изменить решение

- c01-purpose — сильнее, чем проверено: полное соответствие Git и вложенным ignore-файлам не установлено. Если корпус выявит расхождения, сначала уточнить требуемую семантику и выбрать адаптацию либо другой matcher.
- c02-io: метод чтения подавляет OSError. Если приложение не сможет надёжно отличать недоступную конфигурацию от отсутствующей, использовать API без дополнительной диагностики недостаточно.
- c01-license/c02-license: зафиксированы документы, а не разрешение любого способа распространения. Требования проекта к зависимостям пока неизвестны.
- c01-unknown: отсутствие записей в исходное дерево и общий результат не проверены. Авторский тест r01 содержит assertion, но не запускался; для r02 найдена только настройка внешнего тестового корпуса.

## Следующий ограниченный эксперимент

План и ожидаемые результаты — [VALIDATION.md](VALIDATION.md). После отдельного разрешения выполнения: собрать одно временное дерево из 6–8 текстовых файлов, зафиксировать hashes до запуска, применить обе библиотеки на указанных commits и сравнить полный отчёт с ожидаемым. Проверить отрицания ignore, вложенную .editorconfig, root=true, недоступный файл политики и неизменность входов. Успех — все содержательные проверки выполнены, ноль неожиданных изменений, ошибки доступа различимы; одного exit code 0 недостаточно.

Этот обзор завершает только заявленный статический объём. Точка продолжения и незакрытые проверки сохранены в [STATE.md](STATE.md).
