# r02 — editorconfig-core-py

**DEMONSTRATION / OVERVIEW.** Кандидат на подсистему получения правил оформления. Просмотрен путь от API к чтению .editorconfig; библиотечный результат — свойства, а не доказанный отчёт о нарушениях. Все запуски NOT_RUN.

## Идентичность и просмотренный объём

[editorconfig/editorconfig-core-py](https://github.com/editorconfig/editorconfig-core-py), master, commit [e1298e0b8c66041f2e32e84d7c7bbe99ffdba339](https://github.com/editorconfig/editorconfig-core-py/commit/e1298e0b8c66041f2e32e84d7c7bbe99ffdba339). API: public, fork=false. Описание «Clone of EditorConfig core» не превращает репозиторий в GitHub fork: это Python-реализация общего проекта; история заимствований целиком не исследована.

Прочитаны README, pyproject, COPYING, LICENSE.BSD, __init__, handler, ini, .gitmodules и CMakeLists. Просмотрена структура. Полный fnmatch, CLI, тексты PSF-лицензии, содержимое tests-субмодуля и runtime CI не просмотрены.

## Применимость, готовность, доказанность

**Полезность:** высокая для C2 — может заменить поиск, разбор и объединение правил оформления. В просмотренном API возвращаются свойства; валидатор содержимого и отчёт остаются отдельной работой (INFERENCE, c02-role). Не доказано отсутствие готового валидатора во всём проекте.

**Готовность:** основной путь и настройка тестов найдены; ошибки чтения и краевые случаи требуют проверки. Приоритет HIGH — порядок проверки, без общего числового балла.

**Доказанность:** DOCUMENTATION + SOURCE; запуск, сборка, тесты и интеграция не выполнялись. [Реестр доказательств](../EVIDENCE.json).

## Риски и следующий шаг

Контрпример сильному выводу «API достаточно для контролируемой проверки»: возвращённые свойства ещё не показывают, что содержимое им соответствует, а подавление OSError может скрыть проблему чтения. Для первого корпуса нужен вложенный .editorconfig, root=true и недоступная конфигурация; также нельзя молча читать пользовательские политики выше выбранной границы проекта.

**Резюме:** полезен как подсистема определения правил; не подтверждён как готовый checker. Проверены основной путь чтения и документы, тестовый субмодуль только обнаружен. Предлагается использовать публичный API в следующем эксперименте, добавить собственную проверку содержимого и диагностику области/ошибок чтения, затем оценить результат на фиксированном корпусе.
